> 作品名：**苏小师（SuMate）**　队伍：制梦队　版本：v5.0　日期：2026-11-23

> 本文为作品说明文档，包含环境依赖与一键安装、部署运行、开源组件、码道应用总结四部分。
>

## 0. 作品概述

苏小师面向江苏师范大学学生，把分散在群聊、通知、表格和不同系统里的校园事务收进一个入口，覆盖校园导航、预约与签到、文件识别、消费决策、找搭子、自我控制和报修等场景。

技术形态为 **FastAPI 单体后端 + SQLite + 原生 HTML/CSS/ES Module 前端**，默认无前端构建步骤，Windows 下双击脚本即可安装和运行。

| 项目 | 内容 |
|---|---|
| 运行端口 | 5600（可用环境变量覆盖） |
| 数据库 | 项目内 SQLite 单文件 `data/aishida.db` |
| 前端 | 原生 ES Module + CSS，Hash 路由，无框架、无构建 |
| 后端 | FastAPI + SQLAlchemy，统一 `/api` 前缀 |
| 智能能力 | 规则优先、知识库检索、模型兜底；外部服务不可用时明确降级 |
| 运行依赖 | Python 3.10+；Node.js 非必需 |

## 1. 环境依赖说明与一键安装

### 1.1 运行环境

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 / 11 | 启动与安装脚本为 PowerShell / 批处理 |
| Python | 3.10 或更高 | 需包含 `venv` 与 `pip`；建议安装官方 Python 并勾选 Add Python to PATH |
| PowerShell | 5.1 或更高 | Windows 10/11 自带 |
| 浏览器 | Chrome / Edge / Safari 最近两个大版本 | 前端使用 ES Module 与 Fetch API |
| 磁盘 | 约 300 MB（含虚拟环境与数据库） | 不含可选的 `cloudflared.exe` 与模型缓存 |
| 网络 | 安装依赖时需要；运行时可离线 | 首次 `setup` 从镜像安装 Python 包 |

以下组件**不需要单独安装**：

- SQLite：Python 自带 `sqlite3`；
- Node.js / npm：默认前端不做打包，不需要；
- 数据库服务：SQLite 为单文件，无需 MySQL/PostgreSQL。

以下组件为**可选**：

- `cloudflared.exe`：公网演示隧道，已随项目 `tools/` 提供；
- 高德 Web 服务 Key：用于真实步行路线；
- AI 模型网关配置：用于苏小师问答与文档理解；
- Node.js 18+ 与 `esbuild`：仅在自行启用 bundle 构建时需要。

### 1.3 一键安装（推荐）

首次运行双击：

```bat
setup.cmd
```

`setup.cmd` 会调用 `setup.ps1`，执行流程如下：

1. 优先使用 Windows 官方启动器 `py -3.10`；找不到则尝试 `py -3`，再退回系统 `python`；
2. 在项目根目录创建独立虚拟环境 `.venv`；
3. 检测 `.venv` 是否带 `pip`，缺失时执行 `ensurepip --upgrade` 自动修复；
4. 清理本机残留的 `HTTP_PROXY` / `HTTPS_PROXY`，设置 `NO_PROXY=*`，避免代理导致 pip 证书失败；
5. 升级 pip 并使用清华镜像安装依赖：
   `https://pypi.tuna.tsinghua.edu.cn/simple`；
6. 镜像安装失败时自动回退官方源；
7. 导入 `fastapi`、`uvicorn`、`sqlalchemy` 做依赖校验；
8. 提示“以后直接运行 `start.cmd`”。

安装成功后：

```text
.venv\Scripts\python.exe
```

会被 `start.cmd` / `start.ps1` 优先使用。若使用已自带 `.venv` 的可运行作品包，可跳过 `setup.cmd`，直接运行 `start.cmd`。

### 1.4 手动安装（备选）

如果不想运行脚本，可手动执行：

```bat
py -3.10 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r backend\requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

依赖校验：

```bat
.venv\Scripts\python.exe -c "import fastapi, uvicorn, sqlalchemy; print('ok')"
```

> Anaconda 用户注意：用 `python -m venv` 创建的 `.venv` 可能不带 pip。`setup.ps1` 会先尝试 `ensurepip`；若仍失败，会提示使用 conda 方案：
>
> ```bat
> conda create -n sumate python=3.10 -y
> conda run -n sumate pip install -r backend\requirements.txt
> conda run -n sumate python backend\run.py
> ```

### 1.5 配置文件

复制配置模板：

```bat
copy .env.example .env
```

`.env` 可配置项：

| 配置 | 是否必需 | 用途 |
|---|---|---|
| `AI_ENDPOINT` / `AI_MODEL` / `AI_API_KEY` | 可选 | 苏小师问答、文档字段提取、OCR |
| `AI_FALLBACK_ENDPOINT` / `AI_FALLBACK_MODEL` / `AI_FALLBACK_API_KEY` | 可选 | 主模型失败时的备用网关 |
| `AMAP_KEY` | 可选 | 高德地图 Web 服务 Key，用于真实步行路线 |
| `OBS_ENDPOINT` / `OBS_BUCKET` / `OBS_ACCESS_KEY_ID` / `OBS_SECRET_ACCESS_KEY` | 可选 | 华为云 OBS 材料留档 |

安全约定：

- `.env` 含密钥，已被 `.gitignore` 忽略，不进入公开仓库；
- 未配置模型服务时，苏小师会明确提示降级，不伪造答案；
- 未配置 `AMAP_KEY` 时，导航只显示直线距离示意，并明确告知用户。

### 1.6 安装常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示未找到 Python | 未安装或未加入 PATH | 安装 Python 3.10+，勾选 Add Python to PATH，重开命令行再运行 `setup.cmd` |
| pip 安装 TLS/证书失败 | 本机代理配置异常 | `setup.ps1` 已清理代理；仍失败时关闭代理或改用手机热点 |
| `python -m venv` 后没有 pip | Anaconda / 精简 Python | 按 1.4 的 conda 方案执行，或改用官方 Python |
| 依赖安装慢 | 镜像网络波动 | 脚本已使用清华镜像；失败会自动回退官方源，也可重试 |
| 目标电脑不能联网 | 无法下载依赖 | 在联网电脑完成 `setup.cmd` 后整体复制 `.venv`；跨电脑复制建议路径保持一致 |

## 2. 部署运行步骤

### 2.1 本机启动

1. 将 `campus-smart-agent` 文件夹放到目标电脑；
2. 首次运行 `setup.cmd` 安装依赖；
3. 如需 AI/地图能力，复制 `.env.example` 为 `.env` 并填写配置；
4. 双击 `start.cmd`；
5. 浏览器自动打开 `http://127.0.0.1:5600`。

`start.cmd` → `start.ps1` 的实际流程：

1. 检测 5600 是否已有服务在监听；若已运行，直接打开浏览器并打印局域网地址；
2. 优先使用项目内 `.venv`，找不到时回退到同级 `campus-smart-service/.venv`；
3. 启动前导入校验 `fastapi`、`uvicorn`、`sqlalchemy`，依赖缺失时提示先运行 `setup.cmd`；
4. 通过 WMI/CIM 创建**独立于当前命令行窗口**的进程，避免关闭窗口后服务被系统回收；
5. 轮询 `http://127.0.0.1:5600/api/health`，成功后打开浏览器；
6. 打印“本机访问”和“同学访问（局域网 IP）”两个地址。

启动成功后：

| 地址 | 用途 |
|---|---|
| `http://127.0.0.1:5600` | 本机访问 |
| `http://本机局域网IP:5600` | 同一校园网的同学访问 |
| `/api/health` | 健康检查 |
| `/docs` 与 `/openapi.json` | 出于安全审计默认不对外暴露 |

### 2.2 局域网访问

同一校园网内的同学可直接访问 `http://本机IP:5600`。

如果打不开：

1. 确认本机浏览器能打开 `http://127.0.0.1:5600`；
2. 以管理员身份运行 `allow_firewall.cmd`，放行 TCP 5600；
3. 部分校园网开启 AP/客户端隔离，同 WiFi 设备也不能互访，此时改用手机热点或公网隧道；
4. 手机端也可运行 `allow-phone-access.cmd` 检查放行状态。

### 2.3 公网演示（可选）

项目提供 cloudflared 快速隧道，仅用于演示：

```bat
python tools\run_public.py backend
python tools\run_public.py tunnel
```

- `backend` 模式启动后端；
- `tunnel` 模式用 `tools/cloudflared.exe` 把 `http://127.0.0.1:5600` 映射为 `https://*.trycloudflare.com`；
- 每次启动生成的公网地址会变化，以控制台输出为准；
- 公网演示**没有统一身份认证**，不要录入真实敏感信息；演示结束应关闭隧道。

公网访问依赖第三方服务可用性；不承诺长期稳定。

### 2.4 停止、重启与日志

| 操作 | 命令 / 方式 |
|---|---|
| 停止服务 | 双击 `stop.cmd`（结束 5600 监听进程） |
| 重启 | `stop.cmd` 后再次 `start.cmd` |
| 后端日志 | `backend/server.log`；`run_public.py` 模式写入 `logs/server.log` |
| 隧道日志 | `tools/tunnel-console.log`、`tools/tunnel-live.jsonl` |
| 端口修改 | 设置环境变量 `AISHIDA_HOST`、`AISHIDA_PORT` 后启动 |

> 不要用终止未知端口进程的方式“清理端口”；`stop.cmd` 只处理 5600。

### 2.5 数据、初始化与迁移

- 数据库：`data/aishida.db`（SQLite 单文件，可能伴随 `-wal`、`-shm` 文件）；
- 首次启动：自动建表并写入种子数据；
- 历史迁移：聊天会话、搭子活动等模块在启动时做幂等补列/回填（历史库无需手工改表）；
- 地点迁移脚本：`backend/scripts/migrate_places_osm.py`，执行前自动备份数据库；
- 备份：先 `stop.cmd`，再整体复制 `data` 目录（含 `-wal`/`-shm`）；
- 恢复：停止服务，用备份文件替换 `data` 目录，再启动。

### 2.6 前端资源说明

- 默认使用原生 ES Module：`web/static/js/app.js` 直接由浏览器加载，**无需构建**；
- `web/index.html` 通过 `?v=` 版本号引用 JS/CSS；
- 后端对静态资源返回 `Cache-Control: no-cache`，避免更新后浏览器继续使用旧脚本；
- `tools/build_assets.js` 是**可选的** esbuild 打包方案，需要 Node.js 18+ 与 esbuild；当前交付默认不依赖它。

### 2.7 验收命令

| 命令 | 说明 |
|---|---|
| `.venv\Scripts\python.exe backend\smoke_test.py` | 只读冒烟测试：健康、首页、校历、地点、路线、AI、后台汇总 |
| `.venv\Scripts\python.exe -m pytest backend\tests` | 单元测试（需开发期安装 pytest） |
| `.venv\Scripts\python.exe verify_buddy_activity.py` | 找搭子活动化验收：创建、申请、通过、满员、取消通知、清理等 |
| `.venv\Scripts\python.exe backend\scripts\...` | 数据迁移/种子脚本，执行前先备份数据库 |

### 2.8 运行故障排查

| 现象 | 排查顺序 |
|---|---|
| 页面打不开 | 端口是否监听 → `/api/health` → `backend/server.log` |
| 局域网打不开 | 防火墙 5600 → AP 隔离 → 手机热点 |
| 点击后提示 `Failed to fetch` | 服务是否在重启/掉线 → 健康检查 → 重试；启动脚本应使用 WMI 独立进程 |
| 地图底图空白 | 浏览器网络能否访问高德瓦片 → 静态资源版本 → 控制台网络面板 |
| 路线只有直线 | `.env` 是否配置 `AMAP_KEY` → Key 额度/白名单 → 重启服务 |
| AI 不回复或答“未检索到” | `.env` 模型配置 → 网关可用性 → 知识库是否命中 → 降级提示 |
| 页面是旧版本 | 强制刷新（Ctrl+Shift+R）→ 检查静态资源 `?v=` → 服务端 no-cache |
| 端口被占用 | 用 `netstat -ano` 筛选 5600 → `stop.cmd`；不要结束其他未知进程 |

### 4.1 使用方式与证据链

交付材料中的 `codedao_proof/` 按四类保留了开发痕迹：

本文第 4 节只总结方法与效果，具体对话与截图以 `codedao_proof/` 为准。

### 4.2 典型应用场景

#### 案例一：真实地图导航从“示意图”升级为真实路线

- 需求：用户明确否定“假坐标 + 示意图”，要求真实地图、可打标记、手机可定位。
- 码道参与：
  1. 从 OpenStreetMap 获取泉山校区真实地点（敬文图书馆、田家炳工学院、七食堂等），完成 WGS-84 → GCJ-02 转换；
  2. 本地化 Leaflet 与高德瓦片，重写导航页，支持地点标记、搜索、定位、路线绘制；
  3. 后端接入高德 Web 服务步行路径规划，未配置 Key 时明确降级为直线；
  4. 同步迁移资源关联（实验室、教室、座位挂到真实楼栋）。
- 结果：页面从“示意地图”变为真实底图与真实步行路线；地点库、迁移脚本、前端地图和 AI 导航卡片保持一致。

#### 案例二：找搭子从“测试推荐”重构为“活动匹配”

- 需求：原页面同时放性格推荐、附近同学、抽纸条、搭子墙，用户“看了很多却不知道下一步点什么”；要求改为活动报名与参与。
- 码道参与：
  1. 设计三页结构（找活动 / 我的活动 / 申请与消息）与独立发布、详情页；
  2. 扩展活动模型：类型、校区地点、起止时间、总人数、参与要求、报名截止、状态机；
  3. 实现申请 / 邀请的严格区分，满员、停止招募、取消、结束、撤回、退出等状态；
  4. 编写 20 项端到端验收脚本，覆盖重复申请、满员拦截、取消通知、聊天建立与测试数据清理。
- 结果：用户无需先做性格测试即可申请；每种状态都有明确按钮；发布者能处理申请，通过后能进入聊天。

#### 案例三：苏小师多会话、人格化与通用工具

- 需求：头像难看、不能新建会话、回复太机械、只能查今天天气。
- 码道参与：
  1. 新增 `chat_sessions` 与 `session_id`，旧消息自动归入默认会话，前端改为三栏会话界面；
  2. 重写 system prompt，设定“江师大百事通苏小师”，要求清晰、俏皮、不确定就直说；
  3. 新增工具层：Open-Meteo 天气（免 Key，支持 1–7 天与 24 个城市）、时间、计算，并预留 MCP 扩展入口；
  4. 修正天气缓存键与“提示 10 分、实际 2 分”的文案不一致问题。
- 结果：多会话可独立保存；天气能查明天/后天/一周/多城市；任务积分提示与后端实际发放一致。

#### 案例四：排错与稳定性治理

- **返回按钮压栈循环**：SPA 返回时先 `pop` 再被路由渲染压回，导致二三级页面来回循环；通过 `suppressPush` 标记修复，并验证四条路径。
- **积分提示错误**：前端写死“+10”，后端规则是 +2；改为按接口返回的 `xp_awarded` 显示，达到上限时提示上限。
- **服务间歇性掉线**：启动进程随父命令行被回收，导致点击出现 `Failed to fetch`；改用 WMI/CIM 创建独立进程并轮询健康检查。
- **静态资源旧版本**：加入 `?v=` 版本号与服务端 `no-cache`，避免用户继续执行旧脚本。
- 方法：用 CDP/Playwright 检查 DOM、网络请求与控制台异常，用真实鼠标事件复核点击热区，而不是只看语法通过。

#### 案例五：交付工程化

- 补齐 `setup.cmd` / `start.cmd` / `stop.cmd` / 防火墙脚本 / 公网隧道脚本；
- 生成 `requirements.txt`、`.env.example`、迁移脚本、冒烟测试与验收脚本；
- 统一 README、PPT 文案与答辩口径（如导航只写“路线规划 + 分步指引”，不写“实时导航”）；
- 清理测试活动、测试积分与临时文件，避免污染演示数据。

### 4.3 实际工作流

1. **读需求与现状**：先定位页面、接口、模型和种子数据，确认现有行为与数据边界；
2. **拆实现点**：把口语需求拆成前端交互、后端接口、数据库状态、验收标准；
3. **小步修改**：一次改一个闭环，改完立即做语法检查、接口请求或浏览器操作；
4. **真实验证**：用真实请求、真实鼠标事件、手机视口复现；截图与 DOM/网络结果互相印证；
5. **清理与交付**：删除测试数据、更新版本号、补文档与脚本。

### 4.4 带来的效果

- **缩短定位时间**：跨前端视图、后端路由、模型、迁移脚本的改动可以一次梳理，减少来回搜索。
- **跨层一致性**：改一个状态机时，能同步检查页面按钮、接口校验、数据库字段和验收脚本。
- **验证闭环**：从“看起来改好了”变成“接口返回、页面点击、控制台无报错”三者都通过。
- **交付完整度**：安装、启动、停止、配置、迁移、测试、文档可以一起补齐，而不是只交源码。

### 4.5 注意点与边界

- 生成代码必须实际运行验证，语法通过不等于功能可用；
- 外部模型、地图、天气、隧道都可能不稳定，必须准备降级路径与明确提示；
- 前端有缓存与进程回收问题，改动后要强刷、重启并检查真实请求；
- 密钥、`.env`、数据库和真实材料不进入公开仓库；
- 测试预约、测试活动、测试积分必须清理；
- 码道的产出需要人工判断与验收，不能替代产品决策与数据责任。
