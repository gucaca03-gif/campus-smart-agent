# 苏小师 · 江苏师范大学校园智慧服务平台

> 英文名：**SuMate** · JSNU

> 作品说明文档 / README

苏小师是面向江苏师范大学学生的一站式校园智慧服务平台，覆盖校园导航、预约与签到、文件识别、消费决策、找搭子、自我控制和报修等高频场景。项目以“少跑腿、少迷路、做更清楚的决定”为目标，把分散在群聊、通知、表格和不同系统里的校园事务，收进一个统一入口。

> 本作品为校园服务演示系统，预约号、演示档案和演示账号均为系统内数据，不代表学校真实业务状态。

## 一、项目简介与核心创新

### 1. 校园导航：通用地图搜不到的楼栋，这里能搜到、能走到

通用地图通常只能导航已收录的 POI，校园里的楼栋简称、内部工位、临时点位往往搜不到。苏小师提供：

- 校园专属地点库，覆盖学院、食堂、场馆、宿舍、工位和校门。
- 别名识别：静远楼、9 号楼、21 世纪大楼可以指向同一地点。
- 地图内自定义标注：点“标记地点”，在地图上选点、填写名称、类型和标签即可保存，不需要导入 JSON。
- 真实步行路线：配置高德 Web 服务 Key 后，显示沿道路的距离、时间和分步指引；未配置时明确降级为直线示意。
- 需要实时导航时，一键打开高德地图 App。

### 2. 文件识别：聊天转待办、字段提取、材料核查三合一

- 聊天记录转待办：一段群聊通知可直接整理成个人待办。
- 字段提取：上传 PDF、Word、图片等文件，提取姓名、学号、证书编号等关键信息。
- 多材料交叉核查：多份材料逐项对照标准值，缺项和不一致一眼可见。
- 无纸化学生档案示例：身份证、高中毕业证、录取通知书、学籍在线验证报告四份材料，对照录取信息核对姓名、身份证号、毕业学校、毕业时间、专业和学号等字段。

### 3. 省一省：把“想买”变成可比较、可冷静的购买计划

- 建立购买计划，写清商品、预算、使用场景和替代方案。
- 查看公开网页上的多来源价格参考区间，不虚构“实时最低价”。
- 在“大家怎么看”中查看同学讨论和投票。
- 设置冷静期，最后由用户自己决定买、暂缓或放弃。

### 4. 苏小师知识库：回答有依据，下一步能直接办事

- 将研究生手册、发展党员工作实施办法等校内制度文档整理为可检索的校园知识库。
- 回答校历、奖助、党员发展、办事流程等问题时优先引用校内资料；不确定的内容不编造。
- 从“回答”延伸到“办事”：预约研讨教室、打开校园导航、进入省一省、查看校历等都可以一步直达。

### 5. 自我控制：完整的学习闭环工作台

今日待办、长期计划、专注时钟、记录、成就与积分形成一个闭环：

- 今日任务显示完成率、逾期提醒和每日完成情况。
- 专注页显示近 7 天专注趋势；专注时钟离开页面自动保存，返回后可继续。
- 完成任务和专注积累积分，积分对应徽章成长。
- 学习状态可量化、可回溯，不是简单的待办清单。

## 二、功能总览

### 首页与通道

- 首页展示校情数据、校历、校园动态、今日待办和预约提醒。
- 顶部为苏小师自然语言入口。
- 工作区、生活区按场景聚合服务；通道页按校园工作、教务资源、校园生活、个人与自我、智能服务分组。

### 苏小师

- 多会话：新建、切换、重命名、删除对话。
- 意图识别与工具调用：校历、校情、天气、时间、计算、找搭子、省钱计划等。
- 知识库问答与动作卡：回答后可打开对应页面或预约候选。
- 外部模型不可用时明确降级，不伪造答案。

### 校园导航

- Leaflet + 高德公开瓦片，浏览器定位后从当前位置规划路线。
- 31 个校园点位，支持别名搜索、地图标记、自定义地点新增和删除。
- 路线卡显示起点、终点、距离、分钟数和步骤；可跳转高德地图。

### 一键预约与图书馆签到

- 空教室、图书馆座位统一预约。
- 我的预约按待审批、待签到、进行中、已结束、已取消分组。
- 图书馆签到窗口为预约开始前 15 分钟至开始后 15 分钟。
- 签到 +10 积分（按预约组每日一次）；暂离保留 30 分钟；提前离场不再追加时长积分。
- 签到页显示座位、阅览室、预约日期和可签到时间。

### 文件识别

- 聊天转待办、字段提取、文件核查匹配三个页签。
- 支持 PDF、图片、Word、Excel、文本等格式；扫描件走图片识别通路。
- 演示材料覆盖文本 PDF、扫描件 PDF、图片 Word、文本 Word 四类解析方式。

### 省一省

- 购买计划、投票讨论、公开价格参考、冷静期。
- 我的发布与待决策计划。
- 统计只展示计划金额、暂缓金额、放弃金额；“投票只作参考，不改变你的个人决策”。

### 找搭子

- 找活动、我的活动、申请与消息三导航。
- 活动发布、申请加入、邀请、停止招募、取消、结束。
- 个人档案、趣味问答、摇一摇发现同学、站内聊天。

### 自我控制

- 今日：待办、完成率、逾期提醒、每日完成情况。
- 计划：收件箱、任务排期、月度完成情况。
- 专注：专注时钟、任务绑定、近 7 天专注趋势；离开自动保存。
- 记录：随手记、标签、转任务。
- 成就：积分、等级、徽章墙、主题皮肤。

### 报修与我的

- 报修提交、处理中/已完成筛选、处理进度跟踪。
- 我的：预约、搭子、报修、个人档案和主题设置。

## 三、技术架构与目录结构

### 架构

- 后端：Python 3.10+、FastAPI、SQLAlchemy、SQLite。
- 前端：原生 ES Modules + CSS，无前端框架运行时依赖。
- 地图：Leaflet 1.9.4 + 高德公开瓦片；路线可选高德 Web 服务。
- 文档处理：PyMuPDF/pypdf 解析 PDF；Word/Excel 使用内置 ZIP/XML 解析，无需额外 Office 依赖。
- 前端加载：原生 ES Module 直接加载源码（`app.js` 与 `views/`），无构建步骤。
- 数据：SQLite 单文件数据库，默认 `data/aishida.db`。

## 四、环境依赖与一键安装

### 运行环境

- Windows 10/11；Python 3.10 或更高；SQLite 内置，无需单独安装。
- 开发验证环境：Python 3.10.2、FastAPI 0.115、SQLAlchemy 2.0、PyMuPDF 1.27。

### 依赖清单

`backend/requirements.txt`：

```text
fastapi>=0.110
uvicorn>=0.27
sqlalchemy>=2.0
PyMuPDF>=1.24
pypdf>=4.0
python-multipart>=0.0.9
```

### 一键安装

双击 `setup.cmd`。脚本会创建项目内 `.venv` 并安装依赖：优先使用 `py -3.10`，没有则用系统 `python`；自动处理缺 pip、异常代理和镜像源，装完会校验依赖是否齐全。

```bat
setup.cmd
```

不能联网时，提前准备好依赖，或把已安装的 `.venv` 一起复制；换电脑建议重新执行 `setup.cmd`，避免虚拟环境路径失效。

### 配置文件

```bat
copy .env.example .env
```

按需填写：

- `AI_ENDPOINT`、`AI_MODEL`、`AI_API_KEY`：苏小师与文件理解服务。
- `AI_FALLBACK_*`：备用模型服务。
- `AMAP_KEY`：高德 Web 服务 Key，配置后可显示真实步行路线。

未配置模型时功能会明确降级，不会伪造结果。`.env` 含密钥，已被 `.gitignore` 忽略，不要提交到公开仓库。

## 五、部署运行步骤

1. 将整个 `campus-smart-agent` 文件夹复制到目标电脑。
2. 首次运行 `setup.cmd` 安装依赖。
3. 需要 AI 与真实路线时，配置 `.env`。
4. 双击 `start.cmd` 启动，浏览器打开 `http://127.0.0.1:5600`。
5. 停止运行 `stop.cmd`。

补充说明：

- 端口默认 5600，可用 `AISHIDA_HOST`、`AISHIDA_PORT` 覆盖；健康检查 `/api/health`。
- 首次启动自动建表并写入演示数据。
- 局域网打不开时，用管理员身份运行 `allow_firewall.cmd` 放行 TCP 5600。
- 接口文档与 OpenAPI 端点未对外暴露。

前端为原生 ES Module，无构建：修改 `web/static/js` 或 `web/static/css` 后刷新即生效；样式残留可按 Ctrl+F5 强制刷新。

快速验收与单元测试：

```bat
.venv\Scripts\python.exe backend\smoke_test.py
.venv\Scripts\python.exe -m pytest backend\tests
```

## 七、码道在项目开发中的应用总结

项目开发全程使用华为云码道（CodeArts）代码智能体，主要做四件事。

### 1. 需求拆解与实现

把“签到时间不对”“导航要能自己标点”“文件识别示例不好”这类需求，拆成页面、接口、数据状态和验收点，逐项实现。以图书馆签到为例：签到窗口、组级签到、积分口径和签到页提示一起改，前后端一次对齐。

### 2. 跨文件修改与数据脚本

修改导航、预约、文件核查时，同步检查页面、接口、种子数据和静态资源引用。地点导入、知识库导入、演示档案生成、数据库迁移和种子修复都由脚本完成；涉及清空数据、重新初始化、坐标纠正的操作，先备份再执行，最后用接口验证。

### 3. 自动化验收

用 Playwright 跑页面截图、按钮点击和表单提交，检查控制台报错；用 curl 和 Python 请求验证接口边界、文件上传、预约签到等异常分支；视觉改动截图复核。

### 4. 文档与交付

生成和维护 README、部署脚本、requirements、`.env.example` 与演示材料；检查外部路径、密钥、数据库和临时文件，避免把运行环境之外的内容带进交付包。

工作方式：先读代码确认现有行为，再小步修改，每步做语法检查或接口验证，用真实请求和截图复核，发现回归继续修正，最后清理验证数据。

实际效果：

- 需求到可运行页面的路径变短，跨层改动能一次检查到位。
- “看起来改好了”变成“点击和接口返回都通过”。
- 依赖、启动脚本、示例配置、数据初始化可以一起补齐。

注意：生成的代码必须实际运行验证；外部服务要准备降级路径；测试预约和临时数据必须清理；密钥与数据库不进入公开仓库。

码道是开发工具，不是运行依赖；运行时只需要 Python 环境和本项目自身依赖。
